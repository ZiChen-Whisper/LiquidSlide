# 按变化刷新预览与界面玻璃

## 行为

- 背景导出时隐藏目标和所有 `ZOrderPosition >= 目标` 的图形。保留每一层原始 `Visible`，在 `finally` 中逐一恢复；包括原本隐藏的图层。PowerPoint 隐藏图形会清掉选区，因此同步恢复选区后才返回。
- “示例 / 真实”玻璃滑块位于预览画面右上角。进入真实模式时读取一次背景；后续仅在选区或几何信息变化并停稳后刷新。
- 实时应用已移除。只有“应用效果”和 Ribbon 的四个材质按钮写入图形填充。
- 参数变化会使未完成的旧任务失效。演示文稿会话 ID、幻灯片 ID、图形 ID、类型、位置、尺寸、旋转、圆角调整、层级与幻灯片尺寸都参与写入前校验。
- 所有宿主渲染事务串行。背景和材质相同时复用帧、不重复写填充；显式“应用效果”仍强制写入。没有持续排队的定时器。
- 描边与阴影各自独立操作；渲染不会自动去除用户描边。

宿主每 250 ms 仅比较选区、位置、大小、旋转、圆角、形状类型、层级与幻灯片尺寸，不读取标签、不导出、不渲染、不修改图形。鼠标按下、宿主请求处理中不检查。信息变化后，连续两次观察相同才通知前端刷新，因此拖动时不持续导出。前端已没有周期截图循环。材质参数调整复用已有背景；关闭面板或返回示例后停止检测。

## 面板与关于窗口

面板沿用官网的蓝紫渐变页首、白色内容区与简洁控件。材质预览继续使用 Liquid DOM，界面控件本身不再运行独立 GPU 合成循环。

背景模糊、玻璃厚度、高光强度、玻璃颜色和染色强度直接显示在“自定义材质”中；其他光学参数与输出设置保留在“高级设置”。应用按钮不再显示箭头。

预览模式只由用户切换。“应用效果”与 Ribbon 材质操作均保持当前模式；隐藏面板暂停选区检测并取消旧任务，重新打开后按原模式恢复。示例模式不启动选区轮询或自动导出。

面板“关于”和 Ribbon“关于”均打开由 PowerPoint 拥有的独立 Windows 对话框，包含版本、官网、GitHub 作者/仓库/Issues 与致谢，不在 WebView 内显示。

## 顶部入口

原来的 `CommandBars.Add` 属于兼容工具栏，不能提供完整的现代 Ribbon 选项卡。现在 COM 加载项实现 `IRibbonExtensibility`，加载内嵌 `Ribbon.xml`，提供四种材质和“打开面板”及“关于”共六个按钮。图标由插件自己绘制，不依赖特定 Office 版本的内置 imageMso 名称。

Ribbon 回调通过 COM 可见的 IDispatch 接口调用。材质命令先记录点击时的选区，再经 WebView2 消息交给共用的渲染流程；网页尚未就绪时保留命令，运行中阻止重复点击。失败通过原生消息框提示。按钮使用稳定 ID，可通过 Office 标准右键菜单加入快速访问工具栏。

参考：[Microsoft 的 COM Ribbon 文档](https://learn.microsoft.com/en-us/office/vba/library-reference/concepts/customize-the-office-fluent-ribbon-by-using-a-managed-com-add-in)、[GetCustomUI](https://learn.microsoft.com/en-us/office/vba/api/office.iribbonextensibility.getcustomui)。

## 限制

写入 PPT 的仍是静态 PNG。移动图形后会更新面板预览，但需要再次点击“应用效果”更新 PPT 填充。当前检测的是所选图形的几何信息，不是任意后台图层的全部内容编辑。

真实预览只展示下方背景和玻璃填充，不合成目标文字、描边、阴影及上方图形。

## 本轮静态检查范围

- 仅检查源码、TypeScript 类型、ESLint 和 diff 空白问题。
- 按用户要求，不运行单元测试、浏览器测试或 PowerPoint，不构建安装包。
- 实际界面效果、刷新流畅度与宿主集成由用户测试；先前版本的测试结果不代表本轮修改已通过运行验证。
